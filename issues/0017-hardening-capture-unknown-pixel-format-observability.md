# Unix `frame_callback` が `PixelFormat::Unknown` のときユーザーコールバックを呼ばない件の観測可能性

Created: 2026-04-02  
Model: Composer 1

## なぜこの対応が必要か

`src/capture.rs` の `frame_callback` は、**`PixelFormat::from_raw` の結果が `Unknown(_)` のとき `return` し、ユーザーコールバックを呼ばない**（約 238 行）。**デバイスが未対応 FourCC でフレームだけ届く**場合、**利用者は気づきにくい**。

## 現状コード（調査結果）

### 参照ファイル

- `src/capture.rs`（`extern "C" fn frame_callback`、約 149〜242 行）
- `src/types.rs`（`PixelFormat::from_raw`、約 35〜41 行）

### フロー

1. C から `pixel_format`（`u32`）が渡る。
2. **`from_raw`** で既知なら `Nv12` / `Yuy2` / `I420`、**それ以外は `Unknown(raw)`**。
3. **`match pf`** で **`Unknown(_) => return`**（238 行）。
4. **`(context.callback)(frame)`（241 行）に到達しない**。

## 提案する実装（段階的）

### レベル 1（ドキュメントのみ・推奨の最小）

1. **`src/lib.rs` のクレートドキュメント**（フレームコールバック節）に、**「ネイティブが未知の FourCC を送った場合、フレームはコールバックに渡らない」**旨を **1〜2 文の日本語**で追加。
2. **`VideoCaptureConfig` または `pixel_format` 指定**の説明に、**「ネゴシエーション結果が未知フォーマットのときの挙動」**を **C 側の仕様とあわせて**書く（**macOS / V4L2 / PipeWire で差がある**なら **「プラットフォームにより異なる」**と書く）。

### レベル 2（ログ・任意）

- **`tracing` 等の導入**がプロジェクト方針に合う場合のみ、**最初の 1 回** `Unknown` を **英語**で `warn!`。**スパム防止**に `static AtomicBool` や `Once` を使う。

### レベル 3（API 変更・破壊的になり得る）

- **コールバックに `Option<VideoFrame>`** を渡す、**別チャネルでイベント**を送る、など。**別設計 issue** 推奨。

## テスト・検証

- **レベル 1**: `cargo doc` で表示確認。
- **レベル 2**: **未知フォーマットを模擬**するのは **C をモックする**のが難しい。**統合テスト**（特定デバイス）のみの場合は **手動確認**に留める。
